# 栈（Stack）队列（Queue）核心知识点总结

### 栈（Stack） 队列（Queue）核心知识点总结

#### 一、核心特性（最根本区别）

| 数据结构 | 核心规则       | 操作口         | 记忆类比        | 核心关键词          |
| ---- | ---------- | ----------- | ----------- | -------------- |
| 栈    | 后进先出（LIFO） | 仅栈顶（单口）     | 堆盘子（最后放的先拿） | 栈顶 push/pop    |
| 队列   | 先进先出（FIFO） | 队尾入、队头出（双口） | 排队买票（先排的先买） | 队尾 push、队头 pop |

#### 二、C\+\+ 标准库核心操作（必记）

##### 1\. 栈（`std::stack`）

头文件：`#include <stack>`

- 核心接口：
  
  - `push(val)`：栈顶入栈（O \(1\)）
  
  - `pop()`：栈顶出栈（无返回值，O \(1\)）
  
  - `top()`：访问栈顶元素（O \(1\)）
  
  - `empty()`：判断是否为空（O \(1\)）
  
  - `size()`：获取元素个数（O \(1\)）

- 底层默认容器：`std::deque`（可指定`vector`/`list`）

##### 2\. 队列（`std::queue`）

- 头文件：`#include<queue>`

- 核心接口：
  
  - `push(val)`：队尾入队（O \(1\)）
  
  - `pop()`：队头出队（无返回值，O \(1\)）
  
  - `front()`：访问队头元素（O \(1\)）
  
  - `back()`：访问队尾元素（O \(1\)）
  
  - `empty()`/`size()`：同栈

- 底层默认容器：`std::deque`（指定`vector`会导致`pop()`效率变低）

#### 三、经典应用场景（按优先级排序）

##### 1\. 栈的核心场景（LIFO 匹配）

- 括号匹配（最经典）：左括号入栈，右括号匹配栈顶左括号则出栈，最终栈空则合法；

- 反转类问题：字符串反转、进制转换（十进制转二进制）；

- 回溯 / 撤销：函数调用栈、编辑器撤销（Ctrl\+Z）、表达式求值；

- 注意：栈无 “队头 / 队尾” 概念，仅能操作栈顶。

##### 2\. 队列的核心场景（FIFO 匹配）

- 循环 / 排队问题：约瑟夫问题（前 m\-1 人移队尾，第 m 人出队）；

- 层级遍历：树的层序遍历、图的广度优先搜索（BFS）；

- 任务排队：打印机队列、线程池任务队列、消息队列；

- 注意：`pop()`仅删除不返回值，需先`front()`取值再`pop()`。

#### 四、C\+\+ 实操关键坑点（避错必看）

1. 栈 / 队列的`pop()`无返回值：新手易直接`pop()`拿值，正确操作是`top()`/`front()`取值后再`pop()`；

2. 队列不建议用`vector`做底层：`vector`的`pop_front()`是 O \(n\)，远慢于`deque`的 O \(1\)；

3. 栈 / 队列无预分配内存接口：需通过底层容器（`deque`/`vector`）实现，常规场景无需手动预分配；

4. 变量命名规范：栈用`st`/`stk`，队列用`q`/`que`，语义化命名（如`bracket_st`或`task_q`）更易读。

#### 五、性能与选型原则

| 维度     | 栈             | 队列            |
| ------ | ------------- | ------------- |
| 核心操作效率 | 所有操作 O \(1\)  | 所有操作 O \(1\)  |
| 空间开销   | 仅存储元素本身       | 仅存储元素本身       |
| 选型关键   | 需 “逆序 / 回溯” 时 | 需 “顺序 / 排队” 时 |

**选型口诀**：
“后进先出用栈，先进先出用队列；反转回溯选栈，循环排队选队列”。

### 最终总结（核心记忆点）

1. 本质区别：栈是 “头进头出”（栈顶），队列是 “尾进头出”，这是所有用法的根本；

2. 操作核心：栈盯`top()`，队列盯`front()`/`back()`，`pop()`只删不返是通用坑；

3. 场景匹配：栈解决 “逆序 / 匹配”，队列解决 “循环 / 排队”，选对结构代码极简且易读。
