# 计算机课程笔记精炼

把学生的课堂关键词和零散记录整理成准确、紧凑、便于复习的 Markdown。保留课程边界和原笔记覆盖范围，不把一章扩写成教材。

## 处理源稿

1. 完整读取用户指定笔记及其直接引用的本地资源。文件名有轻微偏差时，在合理目录内匹配近似名称，不因缺少点号或扩展名立即停住。
2. 整理前列出原稿的知识点与疑问，确保原有关键词没有因改写而遗漏。
3. 将内容区分为：原意保留、表述纠正、必要补充、易错易混。只补足理解本章必需的定义、机制、作用、边界和前置关系。
4. 默认在源稿同目录生成 `<原文件名>-整理版.md`，不覆盖源稿。用户明确要求原地修改时，先保存带时间戳的备份。

## 组织内容

- 使用“章节概览 → 知识模块 → 具体知识点”的分层结构；对比项优先用表格，过程优先用编号步骤或流程图。
- 每个知识点按需要给出一句话定义、核心机制、作用、最小示例和易错点；不存在的项目不要硬凑。
- 使用明确标签区分 `[纠错]`、`[补充]`、`[易错]`、`[易混]`，并解释错在哪里或适用条件是什么。
- 删除重复、空泛和与本章无关的叙述，但保留足够的因果解释，避免只剩名词清单。
- 术语首次出现时给出中英文全称或常用缩写；后文保持叫法一致。课程口径可能不同的内容应标明“以教师/教材定义为准”，不要擅自替老师定论。

## 代码、公式与图示

- 课程内容包含程序或算法时，提供能说明一个核心点的最小代码；使用带语言标识的围栏代码块，必要时附预期输出。伪代码必须明确标注。
- 公式同时说明变量、单位和适用条件，突出最容易混淆的量。
- 只有关系或过程用文字明显难懂时才加入图示。优先选表格、Mermaid、静态分步图或 SVG；仅当时间变化是理解关键且静态步骤明显不足时制作 GIF。
- 用户要求图片、图示、流程演示，或正文中的关系明显依赖空间结构时，必须生成真实可渲染的图示（如 Mermaid、SVG 或图片文件），不要用多行文字箭头、ASCII 图或纯文字描述代替图片。文字箭头只能作为代码含义或命名拆解的辅助说明，不能替代应有的图。
- 图示必须服务于正文中的一个难点，标题、术语和配色须与正文一致，并使用相对路径引用同目录资源。

## 准确性与克制

- 区分协议本身的保证、常见实现行为和应用层可能额外实现的机制；避免把“通常”“可能”写成“必然”。
- 稳定的教材基础知识可以直接整理；涉及版本相关 API、现行标准或存在争议的纠错时，核验权威来源并在正文附近简短标注出处。
- 最终复核原笔记覆盖率、术语一致性、纠错依据、代码/公式自洽性、相对链接和颜色密度。

具体模板、标签色值和最小示例见 [references/note-style.md](references/note-style.md)。凡输出彩色 Markdown 时都读取该文件。
